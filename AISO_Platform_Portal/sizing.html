考量項目與情境差異 💡滑鼠移到下方標籤即展開：納入什麼、沒納入什麼、哪些參數依使用情境而異

  • 模型權重（依量化／精度）
  • KV Cache（層數、KV heads、Context、並行數；混合架構分層算）
  • Runtime 固定開銷與安全餘裕
  • 每卡可規劃容量（預設 90%）
  • TP 分片（2 的次方）與是否需跨節點
  • 並行請求數（人數 × 活躍比例 × 等待回應比例）
  • HA 備援台數與吞吐量需求（選填）
  • 實際速度：TTFT、TPOT、P95
  • DFlash 草稿模型、PLE Offload、aiDAPTIV 卸載
  • Prefix cache 命中、網路互連與跨節點延遲
  • Context：問答 8K、Coding Agent 32K、長文件 128K，KV 約與長度成正比（差 4～16 倍）。
  • 並行請求：內部問答約 10%（40% × 25%），Agent／批次工作高得多，直接決定 KV 大小。
  • 量化：BF16、Q8、Q4 的權重約為 1、0.53、0.31 倍。
  • KV 精度：FP16 改 FP8 可少一半 KV，品質需自行驗證。
  • 模型架構：Dense、MoE、混合 linear attention、sliding window 的 KV 可差數倍；MoE 全部專家都要常駐。
  • 推論框架：vLLM 先保留 KV 池、llama.cpp 依 ctx 配置，Runtime 與可用容量略有差別。
  • Prefix cache：多人共用長 system prompt 時 KV 可共用，這裡的估算偏保守。
